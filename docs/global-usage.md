# 全局用量查询

从左上角 **agent-board 品牌菜单 → 用量查询** 进入，无需选择工作区或任务。统计的是**本台 Board 实际收到的用量记录**，不是某个账号、终端、订阅或整台机器的账单。任务删除后已入库的记录仍保留。不扫描 `$HOME`，不读取凭证、对话文件，也不通过代理转发请求。

## 页面怎么用

1. 选当天、近 24 小时、7/14/30 天、全部历史，或用本地日期时间选择起止。自选范围包括结束分钟，可选择结束时间跟随现在。点击 Agent 快捷筛选，再选供应商、模型或状态；模型选项随供应商变化。具体的「未知」也是可筛选的组，不是某家供应商的别名。
2. 点 **总成本 / 总请求数 / 真实消耗 Tokens / 缓存命中率** 切换图表；「更多指标」展开新增输入、输出、缓存写入、缓存命中。短时段默认按小时，长时段按日，可选柱状/折线。悬停、触摸或聚焦图后用方向键查看时段。`?` 是有记录但没有该数值；不要把空槽、未知或部分覆盖当作零。
3. 「全部历史」显示 53 周日历热力图，有更早数据时可以往前翻。**卡片和表格仍是全部历史**；图例注明当前图段日期与条数。其他范围中，趋势所有时段合起来就是表格的筛选范围。
4. 图表下方的三个标签**不共用分组**：
   - **请求日志 · N**：N 是用量记录条数，**包含轮次与未确认调用**。按完成时间倒序，服务端每页 10/25/50/100 条；同毫秒按不公开的运行键、事件键稳定打破平局。可选日志列；点击行或聚焦时间按钮并回车打开明细。新数据持续到达时，刷新可能移动页界；浏览历史页/明细时暂停自动刷新。
   - **供应商 · N / 模型 · N**：N 是当前范围内各自的不同组数（包括未知组）。同一模型经两个供应商调用，模型表仍只有一组。不拆分无法归属到单一模型的轮次。列为名称、请求数、成本、Tokens、成功率、速度、首字。点表头排序（默认请求数降序，未知最后），点名称钻取。下方可单独展开 **按 Agent 对比**，不占用上述三个标签。
   - 例：一条 Pi 已确认调用和一条 Codex 轮次都有 Tokens 时，日志为 **2 条**，请求为 **1（部分）**；两条记录的已知 Tokens 都纳入总量。成本、成功率、速度不借用另一条记录的值。
5. 「立即刷新」先刷入待写事件再查询；右侧显示最后一次**成功**刷新的时间。设置中可以关闭轮询或选择 5/10/30/60 秒，默认 60 秒。页面不可见时不轮询。查询失败显示错误与重试入口，不把上次筛选结果冒充当前结果。沿用看板浅/深色或系统主题，窄屏筛选与宽表格可局部横向滚动。

部署时，静态页面可能先于正在运行的服务更新。若页面提示「旧版用量接口」，请等正在运行的任务结束，再按正常发布流程载入新版服务；不要为采集历史或测试重启托管中的看板。

## 数据来源与字段定义

| 来源（完成时入账） | 能确认什么 | 不应如何解读 |
|---|---|---|
| Pi `message_end`，只取 assistant | 响应模型（优先 `responseModel`）、显式 `provider`、最终 usage、`stopReason`、可用的 `durationMs`。响应 ID、正数用量或实际完成原因可确认一次调用。`message_update` 只在内存记录匹配本响应的首个非空 `text_delta` 到达时间 | 本地中止/错误的合成消息不自动算请求。不能用模型名前缀、Agent 名或任务配置猜供应商；工具事件、思考事件、最终文本和 `turn_end` 回显都不是首字，也不再次入账 |
| Claude Code `result` | 整轮 Tokens、缓存、`total_cost_usd`、整轮 `duration_ms` 和显式结束状态；`modelUsage` 唯一模型才能归属（无列表时可用显式 `model`） | 不把 `num_turns`、任务成功或 CLI 耗时当作请求数、请求成功或 API 首字；多模型轮次不拆账 |
| Codex `turn.completed/failed` | 轮次完成/失败；从本轮 started→结束可计轮次耗时。输入包含缓存读，新增输入需先扣除缓存读；从显式 `model` / `model_provider` 读取维度（未提供则未知） | 不从整个会话累计量、任务默认模型或进程退出码反推单个调用；不声称有独立缓存写入计数 |
| Cursor、Devin、Kimi、托管 Grok | 快捷键可查看覆盖状态；当前适配器没有已接入并验证口径的最终用量源 | 没记录不代表没运行或免费。不为凑表格去扫描其他 CLI 的会话库，也不把 Grok 的部署投递当模型调用 |
| 升级前记录 | 原有时间、Agent、模型、Tokens、已确认请求和金额原样保留 | 新列可空；旧记录有标记。不给旧记录补造供应商、状态、定价来源、首字或耗时 |

- **时间**是 Board 收到最终记录的时间；提示与查询按浏览器时区。一次 Start/Continue 一个运行键，最终事件按运行键 + 事件键去重（新写入的事件标识取摘要）。过期回调和 stderr 不入账。按批写库，不逐 token 写；不存正文、原始事件、错误消息、URL 或认证字段。采集是尽力而为：进程在最后一批落盘前崩溃、DB 长期不可用且缓冲满，可能有缺口。
- **费用**优先使用事件金额：Pi 可区分供应商上报与模型目录估算；没有供应商确认的 Pi 合成零价是未知。Claude CLI 金额按估算标示。详情标注来源。可以在「数据来源与设置 → 模型定价」增、改、删每百万 Tokens 的输入/输出/读/写四项 USD 单价（允许明确填 0）。**仅给缺价且模型精确匹配、计费分项齐全的记录补估**，不改事件，不覆盖实际金额；改价时已有缺价历史的查询估值也随之变化。未定价不会显示 `$0.00`。显示币种可按手填汇率换算，库和 API 始终是 USD。
- **Tokens** 取可信总量或完整分项之和；推理子计数不与输出重复相加。缓存命中率是有效样本的 `Σ缓存读 / Σ(新增输入 + 缓存读 + 缓存写)`，不是各行百分比平均。Codex 是含缓存输入协议，没有独立的写桶，分母为其可确认的含缓存输入，写入列仍是 `—`。分母为零不显示 0%。
- **成功率**仅以状态已知的已确认调用为分母。Pi 正常结束、长度上限、工具调用是成功；错误和中止不是成功。轮次状态可查但不进入调用成功率，未知不计作失败。
- **首字**是 Pi SDK 请求起点到 Board 观察到对应首个文本增量的毫秒数，不是 HTTP 首包或服务端测量。无法关联、时间矛盾、无文本流则未知。分组显示成功调用已知首字的中位数（偶数样本取中间两项均值）。
- **速度**仅统计成功的已确认调用：输出 ≥100 且有有效首字时，`输出 / (耗时 − 首字)`；缺首字而有耗时、输出 ≥200 时可估算 `输出 / 全程耗时`，带 `≈`。均换算成秒，非正时段或 >10,000 tok/s 剔除。汇总为 `Σ输出 / Σ对应秒数`，优先有首字的样本，只在没有此类样本时显示估算，不混算、不用轮次耗时测速。
- `—` / API `null` 表示未知、无有效样本或无分母；已确认的零保留。**部分**的提示给出已覆盖/筛选记录数。大数使用 K/M/B、费用保留小额精度、延迟标 ms/s；详情可看未缩写数值。

## 与 cc-switch 逐项对照

对照版本 [`078ea4a`](https://github.com/farion1231/cc-switch/tree/078ea4a859c4372d6846383085563b009831aea4)。依据 [中文手册 4.4](https://github.com/farion1231/cc-switch/blob/078ea4a859c4372d6846383085563b009831aea4/docs/user-manual/zh/4-proxy/4.4-usage.md)、[页面及表格源码](https://github.com/farion1231/cc-switch/tree/078ea4a859c4372d6846383085563b009831aea4/src/components/usage) 和验收参考图。手册中仍有四标签的描述；当前源码与参考图是**三张数据表 + 设置中的定价**。

| 上游 | Board 的对应功能或差异 |
|---|---|
| 应用/日期/供应商/模型/状态码筛选 | 全局 Agent 快捷筛选 + 本地日历/滚动时间 + 供应商→模型；真实事件状态筛选替代 HTTP 状态码，联动所有表和卡片。Board 不在网络路由上，不能得出 200/429/500 等码 |
| 四指标、输入/输出/读/写、趋势样式、全年热力图、tooltip | 四卡切指标、展开分项、柱/线、53 周翻段与图例；保留未知和部分覆盖。按 Agent 的比较独立放在表后 |
| 请求日志、可选列、详情、分页、统计排序 | Board 记录详情与两张独立分组表；默认请求数降序。不展示不可观测的逐请求 HTTP 头、请求/返回模型路由、代理倍率或分项实扣金额 |
| 路由采集、会话扫描、手动同步、后台扫描 | Board runner 在任务运行时已采集；同步等价于刷待写批次并重读一致快照。只有可见用量页轮询。不抓外部流量，不提供无效的路由开关或后台磁盘扫描间隔 |
| Codex 重建/备份、特殊代理/Orchestrator 会话导入、归档补价 | 没有对应的外部历史源，不提供清库重建按钮；仅兼容升级已有统计表。任务删除不删除统计；未开启采集或未接入的历史无法复原 |
| 定价预设、增改删、请求/响应匹配、模糊别名、models.dev 导入/自动覆盖 | 上报优先；Board 本地精确模型规则仅估算未知金额。没有代理请求模型配置，也不以近似名字替代模型、内置易过期的价格或联网覆盖用户定价。CLI 自带的目录价保留其来源 |
| 币种/自动汇率、侧栏「今日」、桌面设置 | 支持显示币种、手动汇率、图样式、日志列/页大小、刷新偏好；不接外部汇率服务。品牌菜单不变，打开即默认当天；不在看板任务侧栏额外轮询用量 |

## API 与验证

`GET /api/usage?from=<ms>&to=<ms>&bucket=hour|day`（左闭右开）。可选 `timezone`（IANA，例如 `Asia/Shanghai`）、`offset`（UTC 以东分钟数，用作无 IANA 时区时的回退）、`agent`、`provider`、`model`、`status=success|failed|aborted|unknown`、`providerUnknown=1`、`modelUnknown=1`、`page`（从 1 起）、`pageSize`（1–100）。未知组与具体同维度值互斥。时区分桶区分夏令时重复小时，不以 86400 秒替代本地日历日。

保留 `summary / byAgent / trend / slots`，新增 `logs / providers / models / choices / page / pageSize`。`records` 为日志总条数，`requestRecords` 等为覆盖计数；表签数分别取 `summary.records`、`providers.length`、`models.length`。时段或维度没有可确认值时，求和结果为 null。聚合在数据库内，日志按 `LIMIT/OFFSET` 取当前页；全部历史可用 `chartFrom/chartTo` 指定其中一个图段（按日不超过 372 天，按小时不超过 32 天），不会截短总数。每次查询先刷入待写批次，再用一个 SQLite 读事务 / PostgreSQL repeatable-read 快照查询。`GET/PUT/DELETE /api/usage/prices` 分别列出、保存和删除本地规则；PUT 使用 `{model,input,output,cacheRead,cacheWrite}`，DELETE 使用 `{model}`。

验收使用临时数据目录、随机本地端口、临时 SQLite 和嵌入式 PostgreSQL，没有重启托管服务。覆盖旧表重复迁移、重复事件、Start/Continue、stale 回调、边界/时区、过滤、排序、翻页、缺失/零、加权速度/首字中位数与定价回退。真实 Chrome 测试含 32 条当日记录（31 个可确认调用，4 个供应商组、6 个模型组）和一条更早的旧记录；核对了标签、逐行详情、查询一致性、热力图翻段、失败重试和 390px 深色窄屏。
