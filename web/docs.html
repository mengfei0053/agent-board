存储（Postgres）

任务 / 日志 / 各轮输出 / sideJobs 持久化在 Postgres。

export DATABASE_URL='postgresql://postgres:postgres@127.0.0.1:5432/agent_board'
# 可选隔离实例：docker compose up -d 后改用端口 5433

默认库名 agent_board。首次启动会迁移旧 data/db.json。

概览

看板泳道：draft（草稿）→ todo（queued）→ running → done（succeeded / failed / stopped）→ archived（归档）。

  • 新建草稿：只入库，不 spawn。
  • 新建 Todo：创建后立刻 start（进入 Todo 并开跑）。
  • queued / running 不可删除，需先 stop。

下列 curl 假设服务在 http://127.0.0.1:8791。

Webhook 新建草稿 / Todo

POST /api/hooks/tasks（别名 POST /webhook/tasks）

鉴权：环境变量 AGENT_BOARD_WEBHOOK_SECRET。未设置时返回 503。

  • Authorization: Bearer <secret>
  • 或 X-Webhook-Secret: <secret>
字段必填说明
prompt✅任务内容
agent✅pi | claude | cursor | devin | codex | kimi（别名 kind）
cwd✅工作目录（须已存在）
model可选模型
title可选标题
starttrue → 创建并开跑
lane / modedraft（默认）或 todo
useGitWorktree可选布尔，默认关。仅当 cwd / 工作区路径是带可用 HEAD 的 git 工作树根时可为 true；其它类型 → 400

响应：201 { task, started }

启动时设置 secret

export AGENT_BOARD_WEBHOOK_SECRET='replace-me'
npm start

新建草稿

curl -sS -X POST http://127.0.0.1:8791/api/hooks/tasks \
  -H "Authorization: Bearer $AGENT_BOARD_WEBHOOK_SECRET" \
  -H 'content-type: application/json' \
  -d '{
    "prompt": "整理 README",
    "agent": "pi",
    "cwd": "/home/menghongfei/projects/agent-board",
    "mode": "draft"
  }'

新建 Todo 并开跑

curl -sS -X POST http://127.0.0.1:8791/webhook/tasks \
  -H "X-Webhook-Secret: $AGENT_BOARD_WEBHOOK_SECRET" \
  -H 'content-type: application/json' \
  -d '{
    "prompt": "跑一遍 typecheck 并修错",
    "agent": "claude",
    "cwd": "/home/menghongfei/projects/agent-board",
    "start": true
  }'

UI / API 创建任务

POST /api/tasks（看板表单使用；无 webhook 鉴权，仅本机服务）

字段必填说明
kind✅pi | claude | cursor | devin | codex | kimi
cwd✅工作目录
prompt✅任务内容
title / model可选
starttrue → 创建并开跑（等同「新建 Todo」）
useGitWorktree可选布尔，默认关。为 true 时在工作区根下创建 .agent-board/worktrees/<id>，任务 cwd 指向该目录。不合格、无提交、路径已存在 → 400，且不留下任务或 worktree

新建草稿

curl -sS -X POST http://127.0.0.1:8791/api/tasks \
  -H 'content-type: application/json' \
  -d '{
    "kind": "pi",
    "cwd": "/home/menghongfei/projects/agent-board",
    "prompt": "写一个 hello",
    "title": "demo-draft"
  }'

新建 Todo（创建并开始）

curl -sS -X POST http://127.0.0.1:8791/api/tasks \
  -H 'content-type: application/json' \
  -d '{
    "kind": "pi",
    "cwd": "/home/menghongfei/projects/agent-board",
    "prompt": "只回复 OK",
    "title": "demo-todo",
    "start": true
  }'

启停 / 移动 / 继续

修改任务标题

PATCH /api/tasks/:id body { "title": "新标题" }（非空字符串，最多 200 字符）。

curl -sS -X PATCH http://127.0.0.1:8791/api/tasks/TASK_ID \
  -H 'content-type: application/json' \
  -d '{ "title": "更新后的标题" }'

开始任务

POST /api/tasks/:id/start — 将草稿（或终态任务）拉起 runner。

curl -sS -X POST http://127.0.0.1:8791/api/tasks/TASK_ID/start

移动泳道

POST /api/tasks/:id/move body { "lane": "draft"|"todo"|"running"|"done"|"archived" }

拖到 Todo 等价于 lane: "todo"（会 start）。

curl -sS -X POST http://127.0.0.1:8791/api/tasks/TASK_ID/move \
  -H 'content-type: application/json' \
  -d '{ "lane": "todo" }'

停止

POST /api/tasks/:id/stop

curl -sS -X POST http://127.0.0.1:8791/api/tasks/TASK_ID/stop

继续（迭代）

POST /api/tasks/:id/continue body 可选 { "prompt": "补充说明", "model": "目标模型" }。成功后 iteration + 1，按各 CLI session/resume 续跑。省略 model 沿用当前模型；提供时必须是非空字符串，最多 200 字符。

切换模型仅适用于已有会话且已完成、失败或停止的任务，保留原执行器、会话、目录和历史；无会话或尚未停止的 blocked 任务切换模型返回 409。不接受更改 kind、sessionId、cwd 或 workspaceId。续接失败不自动新建会话或回退模型；上下文窗口与自动压缩仍由 CLI 决定。

curl -sS -X POST http://127.0.0.1:8791/api/tasks/TASK_ID/continue \
  -H 'content-type: application/json' \
  -d '{ "prompt": "接着把测试也补上", "model": "目标模型" }'

批量删除

POST /api/tasks/batch-delete body { "ids": ["id1","id2"] }

queued / running 会进入 skipped，需先 stop。若任务拥有 git worktree，删除会移除该目录；目录里有未提交改动时保留，并在 warnings 中说明。

curl -sS -X POST http://127.0.0.1:8791/api/tasks/batch-delete \
  -H 'content-type: application/json' \
  -d '{ "ids": ["TASK_ID"] }'

curl -sS http://127.0.0.1:8791/api/health

curl -sS http://127.0.0.1:8791/api/tasks

任务详情（含 log 尾部与最终 output）

工作区是否可建 git worktree

GET /api/workspaces/:id/git-worktree-eligibility → { ok: true, root, head } 或 { ok: false, reason }。看板勾选框只用这个结果，不用 git-status 的 relPath。

浏览目录（选 cwd）

curl -sS 'http://127.0.0.1:8791/api/browse?path=/home/menghongfei/projects'

SSE 实时事件

GET /api/events — Server-Sent Events。

  • 连接时先发 hello（带当前 tasks 快照）
  • 之后：task_upsert / task_delete / task_log
  • 约 15s 一次 ping
curl -sSN http://127.0.0.1:8791/api/events

MCP / Skills 统一管理

设置页提供 pi、Claude、Cursor、Devin CLI、Codex、Kimi Code 的分发矩阵，保存到本机用户级配置；工作区 MCP 仍可覆盖。MCP 支持 stdio / HTTP，同名冲突会单独报告，可重试。Skill 支持本地目录和 GitHub HTTPS 仓库的完整包安装，检测到同名目录会自动勾选；勾选直接覆盖，取消勾选直接删除目标 Agent 的同名技能。卸载保留管理中心主副本，允许从本机导入恢复。

GET /api/settings/extensions 返回 revision、mcp、skills、agents、skillStore 和 syncResults。凭据字段显示占位符，编辑时保留占位符即可保留原值。GET /api/settings/extensions/local-skills 列出可导入的本机技能和卸载后保留的主副本。

POST /api/settings/extensions/:action 必须携带最新 revision，过期返回 409。可用操作：

  • save-mcp：{ revision, name, config: { command?, args?, env?, url?, headers? }, apps: ["cursor", "devin"] }
  • set-apps：{ revision, resource: "mcp" | "skills", name, agent, enabled: true | false }，修改单个 Agent；也兼容 { revision, resource, name, apps } 整组选项。
  • delete：{ revision, resource, name }
  • import-mcp：{ revision, agent: "pi" | "claude" | "cursor" | "devin" | "codex" | "kimi" }；仅导入支持的连接字段，其他认证字段与 SSE 会明确拒绝。
  • install-skill：{ revision, name, apps, path? } 或 { revision, name, apps, url, ref?, subdir? }；目录必须包含有效的 SKILL.md，最多 2000 个文件 / 20 MB。
  • sync：{ revision }，按管理清单重新分发。

操作成功返回完整管理文档；HTTP 200 表示管理清单已保存，各目标的实际分发结果须检查 syncResults 的 ok / error。管理清单独立于常规设置的「恢复默认」。

设置（按 Agent：CLI 路径、进程代理与自定义环境变量）

页面：/settings（看板左上角菜单也可进入）。UI 顶部按 Agent 切换，同屏编辑该 Agent 的 CLI 路径、代理与其他环境变量。

GET /api/settings — 返回 cliPaths、按 kind 分桶的 proxyEnv（覆盖值、生效值；空键可显示是否继承看板进程环境）和 processEnv（自定义环境变量，无配置时为空对象）。

curl -sS http://127.0.0.1:8791/api/settings

PUT /api/settings 可传 cliPaths、proxyEnv、processEnv、quickPrompts、codexSandbox 中的任意一组。代理按 pi / claude / agent / devin / codex / kimi 分别配置；空字符串清除该项覆盖。processEnv 按 kind 整体替换（提交的对象即该 kind 的完整集合，空对象清空），变量名须匹配 [A-Za-z_][A-Za-z0-9_]*，代理键与控制面密钥不可设置。

curl -sS -X PUT http://127.0.0.1:8791/api/settings \
  -H 'content-type: application/json' \
  -d '{
    "cliPaths": {"agent":"/home/menghongfei/.local/bin/agent"},
    "proxyEnv": {
      "agent": {
        "HTTP_PROXY": "http://127.0.0.1:7890",
        "HTTPS_PROXY": "http://127.0.0.1:7890",
        "NO_PROXY": "localhost,127.0.0.1",
        "ALL_PROXY": ""
      },
      "codex": {
        "HTTP_PROXY": "http://127.0.0.1:7891",
        "HTTPS_PROXY": "http://127.0.0.1:7891"
      }
    },
    "processEnv": {
      "pi": {"OPENAI_BASE_URL": "https://example.test/v1"}
    }
  }'

全部恢复默认：{ "clear": true }（保留快捷输入）。持久化 meta.cli_paths / meta.proxy_env / meta.process_env（均 per-kind）；旧版全局扁平代理会在启动时复制到全部 kind。保存后对新 spawn 生效。子进程日志仅记录注入的代理键名，不写具体值。

工作区

  • GET /api/workspaces — 列表
  • GET /api/workspaces/:id — 单个（含 settings）
  • POST /api/workspaces — { name, path }
  • PATCH /api/workspaces/:id — { name?, path?, settings? }；settings 为整对象替换：{ systemPrompt?, skills?: string[], mcp? }
  • DELETE /api/workspaces/:id — 无任务时可删（默认工作区不可删）
  • GET /api/workspaces/:id/git-status — 只读 Git 状态。?refresh=1 跳过约 3 秒缓存。不接受客户端路径；仓库根目录只取工作区已保存的 path。

新建任务优先传 workspaceId；cwd 取自工作区 path。看板左侧侧栏管理工区，右侧只显示当前工区任务。选中工作区后，泳道上方展示 Git 状态；空间设置页 /workspaces/:id/settings 也有同样的只读面板。侧栏工作区可右键：设置 / 编辑 / 删除。空间 systemPrompt、skills 和纯文本 MCP 说明在任务首次启动时前置拼入 runner prompt（有 session 的续跑不重复注入）。mcpServers JSON 会在各 Agent 每次启动或续跑时原生加载，支持 stdio 和 HTTP；OAuth 需各 CLI 分别登录，Pi 需 pi-mcp-adapter。清空后下次启动移除看板配置，已有独立配置仍保留。

Git 发现：从工作区根目录向下找 .git（目录或文件，含子模块 / worktree）。根目录深度为 0。上限：深度 6、仓库 32、扫描目录 4000、每个仓库变更行 200。不进入 node_modules、vendor、dist、build、target、.git 内部以及其他常见依赖 / 构建目录。达到上限时响应 truncated: true。接口只跑 git status 与 git log -1，不提交、不推送、不切换分支。
